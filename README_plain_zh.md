# 我们做了什么 —— 大白话版报告

> 这份是给"不看代码、不懂机器学习黑话"的人看的。每个词都翻译成人话。
> 想看带数字和误差范围的技术版,看同目录的 `ANALYSIS_full_ft_v0.md` 和 `data/eval_report.md`。

---

## 一、这事到底在干嘛

我们训练了一个 AI 模型,让它当**"答案纠错员"**。

工作流程是这样的:给它**一道题** + **一个待检查的答案**,它要做三件事:
1. 判断这个答案**对不对**;
2. 如果错了,说出**错在哪一类**、**该用什么方法修**;
3. 给出**修好之后的正确答案**;
4. 如果答案本来就对,**别瞎改**。

训练完之后,我们拿 **550 道它从没见过的新题**考它,看它干得怎么样。

---

## 二、一个真实例子(就是考卷第一题)

- **题目**:《Silver River》这本书的作者是哪国人?
- **待检查的答案**:Drasivian(德拉西维亚人)

**标准答案要求模型**:这个答案是错的(因为题目里缺了"作者到底是谁"这个关键中间信息),
应该判定成"缺少桥接事实",把它补上,算出最终答案是 **Lydorian**。

**模型实际干的**:它说"没毛病,保持原答案",给了 **Drasivian**。
→ 它**漏判了**,没看出这是个错的答案。

## 三、报告里那些看不懂的词,翻译成人话

| 黑话 | 人话 |
|------|------|
| **JSON-valid(JSON 合法率)** | 我们要求模型按一个**固定表格格式**作答(填 4 个空)。这项 = "它填的表格电脑能不能读懂?" 100% = 格式每次都对。**只看格式,不看答案对错。** |
| **diagnosis(诊断)** | 表格第 1 个空:"这答案属于哪类错误?" 看它有没有判对错误类型。 |
| **repair_skill(修复技能)** | 表格第 2 个空:"该用哪种方法来修?" 看它有没有选对工具。 |
| **final_answer(最终答案)** | 表格第 4 个空:改出来的最终答案对不对。 |
| **exact(全对 / 3 项全中)** | 上面三项在同一道题里**全部答对**才算。错一个就不算。最严的标准。 |
| **over-repair(过度修复)** | 答案本来是对的,模型却手贱去改了。 |
| **under-repair(漏修)** | 答案明明错了,模型却说"没事不用改"。(上面那个例子就是。) |
| **[15.8, 22.7] 这种方括号** | **误差范围**。因为只考了 550 题不是无限题,真实水平大概落在这区间,不是一个死数。 |

## 四、结果说人话就是三句话

**第 1 句:"填表格"完全学会了。**
不管答得对不对,格式永远规规矩矩,100% 电脑都能读。

**第 2 句:"看出错在哪、该用什么方法"基本学会了。**
除了一类特别隐蔽的题(下面第五节讲),其他题它判错误类型、选修复方法都接近 100% 准。
也就是说,它能当个合格的"分诊台":告诉你"这道题坏在哪、该找谁修"。

**第 3 句:"真正把答案改对"几乎全军覆没(只有 19%,很多类型是 0%)。**
但这**是我们故意设计成这样的**,不是模型笨,也不是程序错。原因:
- 考题里的人名、地名、国名**全是我们编出来的、现实中不存在的**(比如 Maria Voss、Lydorian);
- 而且**题目里故意不给任何提示**。

模型脑子里根本没有这些虚构知识,所以它**没法凭空编出正确答案**。
这恰恰证明了:**这套考题考的是"真本事"(能不能真的推理/回忆),而不是"背答案"。**
如果换成真实世界的人名地名、或者把提示放进题目,这个分数就会涨起来 —— 这正是下一版要做的对照实验。

## 五、一个有意思的发现

有一类题(代号 H-Aug)模型表现明显比别的差 —— 连"看出有没有错"都只有 30% 准。

原因:这类题的错误答案**看起来特别合理、特别顺**,只是悄悄少了一个关键事实。
模型太容易"信"一个读起来通顺的答案,于是 100 道里有 70 道它都说"这答案挺好,不用改"。

**结论**:最难被发现的错误,是那种"看着没毛病、其实缺了一环"的错误。
模型对明显的矛盾(比如题目里摆着一个明显错误的说法)能 100% 抓出来,
但对这种"安静地少了一块"的错误,会放松警惕。
